# ⚡ Aila Maps Supabase Cloud Configuration Guide

Since you decided to transition from Vercel to **Supabase** for secure cloud API key management and account synchronization, the Android client has been fully configured to integrate with your Supabase REST endpoint:
- **Supabase URL**: `https://tmfoduaorgidxnoeqkfs.supabase.co`
- **Dynamic Key Retrieval**: Instantly pulls dynamic API credentials at runtime.
- **Fail-safe Fallback**: Automatically cascades to local sandbox caching and environment profiles if tables are empty or do not exist, ensuring 100% app uptime.

---

## 🛠️ Step 1: SQL Setup on Supabase (Copy-Paste)

Go to your [Supabase Dashboard](https://supabase.com/), open your project, click on the **SQL Editor** in the left sidebar, paste the following SQL query, and click **Run**:

```sql
-- 1. Create the API credentials table
CREATE TABLE IF NOT EXISTS public."Apis" (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name TEXT UNIQUE NOT NULL, -- e.g., 'GEMINI_API_KEY', 'MAPTILER_KEY', 'ORS_KEY', 'OPENROUTER_KEY'
    value TEXT NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT timezone('utc'::text, now()) NOT NULL
);

-- Enable Read access (SELECT) to everyone (Anonymous Role)
ALTER TABLE public."Apis" ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Allow anonymous read access on Apis" 
ON public."Apis" FOR SELECT TO anon USING (true);


-- 2. Create the Accounts table for cloud synchronization
CREATE TABLE IF NOT EXISTS public.accounts (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    email TEXT UNIQUE NOT NULL,
    password_hash TEXT NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT timezone('utc'::text, now()) NOT NULL
);

-- Enable SELECT & INSERT to anonymous role
ALTER TABLE public.accounts ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Allow anonymous select on accounts" 
ON public.accounts FOR SELECT TO anon USING (true);

CREATE POLICY "Allow anonymous insert on accounts" 
ON public.accounts FOR INSERT TO anon WITH CHECK (true);
```

## 🔑 Step 2: Populating your API Keys

Inside the **Table Editor** on Supabase, select your **`Apis`** table and insert rows for whichever API keys you'd like the app to dynamically leverage:

| `name` | `value` | Description |
| :--- | :--- | :--- |
| **`GEMINI_API_KEY`** | *`AI_STUDIO_KEY`* | Activates direct on-device Conversational chatbot advisor. |
| **`MAPTILER_KEY`** | *`MAPTILER_KEY`* | Activates lightning-fast coordinate lookups and topographic mapping. |
| **`ORS_KEY`** | *`ORS_DRIVING_KEY`* | Activates direct turn-by-turn routing steps on the map. |
| **`OPENROUTER_KEY`** | *`OPENROUTER_TOKEN`* | Fallback chatbot engine. |

*If a key does not exist or is empty in Supabase, Aila Maps will gracefully fallback to direct public routing engines, search engines, and mock coordinates automatically.*

## 🤝 Native Security & GitHub Guard

With this Supabase architecture:
1. **Zero Hardcoded Secrets**: Your keys are kept completely secure in your private cloud database instead of your client bundle.
2. **GitHub Clean**: Build and build caches (`app/build/`) have been added to `.gitignore` to prevent any local generated `BuildConfig.java` from being committed to GitHub.
